## Representation limitations requiring Maria review

The existing JSONB array/API uses exact membership, supports request years 1–6 and excludes nulls. It cannot encode an unbounded minimum, completed semesters at a future start, degree-duration alternatives, graduation windows or programme-relative final/penultimate years. No schema or API contract was changed.

Smallest proposed extension for Maria: nullable `minimum_study_year` (current year, only where officially explicit). Add `study_year >= minimum_study_year` as an alternative predicate; preserve the existing array for exact unconditional rules and null for unknown. This would still NOT model completed years, integrated masters or future milestones; those need separate scoped rules and degree duration/start-date context. Do not enumerate [2,3,4] or [2,3,4,5,6] as an open-ended rule.

Verified alternatives for students earlier than the old 3–4 recommendation include general bachelor/master internships with no published numerical minimum (Stripe, Amazon Poland/Iasi, Arm Software Developer). None proves a universal mandatory "current year 2 or above" restriction. Arm Graphics explicitly encourages integrated-master year 2; this must not be generalized to all bachelor year-2 students.

DIGS-ILS requires four bachelor semesters completed by start; Qualcomm requires second bachelor year completed. ETH now explicitly describes its announced 2027 cycle, requiring two years completed by start. Saarland still describes filled 2026 places; its 2027 conditions remain unconfirmed. Stripe’s one university year is a preference with an equivalent-experience route, not a hard academic minimum.

The existing 50 are candidates, not 50 verified live offers. Exact numeric arrays survive only when unconditional at the academic-year level; additional graduation/work/legal conditions still need human review. Null is unknown/not representable, never permission for everyone.
